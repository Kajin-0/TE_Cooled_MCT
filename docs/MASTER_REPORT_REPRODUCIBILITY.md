## Build and review

Use a NEW staging directory; all work stays in the existing sim Codex session.
The pinned wrappers limit scientific figure work to four CPUs / eight GiB,
within the twelve-GiB project cap. Host TeX Live and MuPDF are already installed.

```bash
python3 -B -m reports.master.build --out outputs/master-rebuild
```

The build re-derives the original actual-field figures with the inspected
generator, then computes new figures/tables from versioned reduced transport,
exchange and scenario data. It does not run a production FEM solve. Native
cap/window sections use the actual candidate tetrahedra; the filled-core proxy
is drawn separately and labeled explicitly. Node/cell field correspondence,
every input hash, figure hash and generator snapshot are recorded separately
from the public PDF.

Three deterministic LaTeX passes resolve the contents and references. Validation
rejects overflow, missing glyphs, unresolved references, forbidden reader/admin
text and identifiers, personal metadata, out-of-page text and blank pages.
Every page is rasterized; pixel/edge checks and two-page review spreads are
written under staging `renders`. Inspect every spread and zoom dense equations,
tables, color scales and new figures before recording `visual_review.json`.
Record the actual PDF digest, page count and actual findings; never mark an
unseen page inspected.

For text/layout iterations with unchanged figures and their source fingerprints:

```bash
python3 -B -m reports.master.build --out outputs/master-rebuild --reuse-figures
```

Changing a figure generator invalidates reuse and requires a fresh figure
build. Rebuild twice with fixed inputs/environment and compare PDF bytes.
Also compare fresh figure hashes against the preceding same-input generation;
retain machine-readable reproduction results. These are report reproduction
checks, not a new physics solve or an uncertainty estimate.

After all page reviews and checks pass:

```bash
python3 -B -m reports.master.build --out outputs/master-rebuild --publish
python3 -B -m reports.master.validate --current
./fem/run.sh python -m pytest -q tests/test_master_finite_sink.py tests/test_master_identifiability.py tests/test_master_material_screening.py tests/test_rev3_master.py tests/test_rev3_review.py tests/test_engineering_report.py
./fem/run.sh python fem/archive_bath_spatial_device.py --verify
./fem/run.sh python -m tecooledmct.cli --quick --out outputs/master-check/legacy-cli
./fem/run.sh python -m tecooledmct.geometry_demo --out outputs/master-check/legacy-geometry
```

These are the bounded report-only gates. A full opt-in physics regression,
including CAD/mesh/Elmer runtime cases, belongs to separately authorized physics
work under the project contract; do not launch those jobs for this frozen-data
integration. Default exact-commit CI additionally runs the standard unit suite
with runtime cases skipped. Neither suite changes archived numerical failures.

Publication first checks the new provenance through the unchanged legacy API,
then updates the canonical bytes and live reference. Unknown/generated-history
directories cannot be overwritten. Previous live build assets move to ignored
outputs; immutable historical originals never move or change. Commit and push
only verified current assets, sources, figures and validation records; check CI
for that exact commit.

## Reader-facing contract

Use professional scientific prose, public technical references, SI equations,
source/assumption and coverage tables, genuine fields and honest numerical
failures. No usernames, filenames, paths, repository identifiers, source hashes,
agent discussion, commands, CI or project diary belongs in the PDF. Exact
machine provenance remains in sidecar files. Do not conflate native CAD with a
coupled field, the proxy with full native-surface exchange, or conservation with
physical accuracy. The original raw bath 1% / cold-interface 5% numerical-release
requirements remain unchanged; an exploratory synthetic reference need not fit
proprietary OEM curves to be scientifically useful.
